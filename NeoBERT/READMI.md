# Обучение модели NeoBERT для задачи extractive QA

В рамках проекта реализована адаптация encoder-only модели NeoBERT для задачи извлечения ответов на длинном контексте с использованием кастомной QA-головы и глубоких аппаратных оптимизаций пайплайна.

## 🚀 Ключевые особенности

* Тонкая настройка (fine-tuning) моделей семейства NeoBERT.
* Кастомная архитектура (AutoModel + кастомная Linear QA-head).
* Оптимизированный пайплайн под видеокарты с поддержкой CUDA 12.4 (протестировано на RTX 4060 16 ГБ).
* Оценка F1-score, Exact Match.

---

## 💻 Использование

### Запуск обучения

Для запуска процесса fine-tuning используйте конфигурационный файл `config.yaml`. Пример запуска:

```bash
python train_neobert_nq_span.py --config configs/config.yaml

```

## ⚙️ Описание конфигурации (config.yaml)

Все основные параметры обучения вынесены в конфигурационный файл формата YAML.

### Основные параметры

* `model_name` — идентификатор модели на HuggingFace (например, `"chandar-lab/NeoBERT"`).
* `train_file`, `validation_file` — пути к обучающему и валидационному датасетам в формате `.jsonl` или `.jsonl.gz`.
* `output_dir` — директория, куда будут сохраняться логи, чекпоинты и результаты.
* `max_seq_length` — максимальная длина последовательности (вопрос + контекст) в токенах.
* `doc_stride` — размер перекрытия окон (stride) при нарезке длинного документа на фрагменты.

### Оптимизация памяти и вычислений

В связи с работой на длинных контекстах параметры оптимизированы для GPU потребительского сегмента:

* `per_device_train_batch_size` — установлен в `1` для предотвращения Out-Of-Memory (OOM).
* `gradient_accumulation_steps` — установлен в `16` для достижения эффективного размера батча без перегрузки VRAM.
* `bf16` / `tf32` (`true` / `false`) — использование смешанной точности и тензорных ядер для ускорения матричных умножений.
* `optim` — выбор оптимизатора (рекомендуется `"adamw_torch"` или `"adamw_torch_fused"` для ускорения).

## 🧠 Описание работы кода

Обучение реализовано в виде скрипта, который реализует следующий пайплайн:

1. **Предобработка данных (Data Pipeline):**
* Модель обучается на предварительно очищенном датасете Natural Questions (NQ).
* Исключены вопросы типа YES/NO, удалена HTML-разметка, отфильтрованы примеры без ответов.
* Датасет читается потоково (`iter_jsonl_or_gz`). Глобальные координаты ответов автоматически пересчитываются в локальные координаты относительно нарезанных окон контекста.


2. **Обучение (Training) и Архитектура:**
* Поскольку NeoBERT является encoder-only моделью и не имеет встроенного класса `AutoModelForQuestionAnswering`, реализована кастомная обертка `NeoBERTForQuestionAnswering`.
* Модель берет скрытые состояния (hidden states) из базового `AutoModel` и пропускает их через линейный слой (`nn.Linear(hidden_size, 2)`), получая логиты для начала и конца ответа.
* Применяется метод аккумуляции градиентов и оптимизированный `DataLoader` (`pin_memory`, `persistent_workers`) для непрерывной загрузки GPU.


3. **Оценка (Evaluation) и Постобработка:**
* Скрипт использует режим "Fast Eval": вместо раздельных шагов оценки и предсказания выполняется один быстрый проход.
* Для экономии ресурсов отключено сохранение тяжелых JSON-файлов с поштучной детализацией предсказаний.
* Вычисляются классические для QA метрики: **Exact Match (EM)** и **F1-score** с официальной нормализацией SQuAD.

## 📈 Результаты обучения

По итогам 2 эпох обучения `chandar-lab/NeoBERT` на выборке NQ получены следующие метрики:

* **Exact Match (EM):** 68.47%
* **F1-score:** 80.98%
* **Eval Loss:** 0.9501
* **Скорость инференса (Eval):** ~45.79 примеров/сек.
