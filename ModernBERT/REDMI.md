# Обучение модели ModernBERT для задачи extractive QA

В рамках проекта реализованы механизмы SQuAD 2.0 (обработка нерешаемых вопросов) и методы компенсации позиционного смещения (position bias) при длинном контексте.

## 🚀 Ключевые особенности
* Тонкая настройка (fine-tuning) моделей ModernBERT.
* Оценка производительности (F1-score, Exact Match).
* Оптимизированный пайплайн под видеокарты с поддержкой CUDA 12.4.

## ⚙️ Описание конфигурации (config.yaml)

Все основные параметры обучения вынесены в конфигурационный файл формата YAML. Это позволяет проводить эксперименты без изменения исходного кода.

### Основные параметры

* `model_name` — идентификатор модели на HuggingFace (например, `"answerdotai/ModernBERT-base"` или модель семейства NeoBERT).
* `train_file`, `validation_file` — пути к обучающему и валидационному датасетам в формате `.jsonl` или `.jsonl.gz`.
* `output_dir` — директория, куда будут сохраняться логи, чекпоинты и результаты предсказаний.
* `max_seq_length` — максимальная длина последовательности (вопрос + контекст) в токенах.
* `doc_stride` — размер перекрытия окон (stride) при нарезке длинного документа на фрагменты.

### Режим SQuAD 2.0 (Обработка примеров без ответа)

* `allow_unanswerable` (`true` / `false`) — если включено, модель учится на примерах, где правильного ответа в тексте нет. В качестве таргета используется `[CLS]` токен. При инференсе применяется null-score thresholding.
* `unanswerable_ratio` (0..1) — доля отрицательных примеров в обучающей выборке (используется даунсэмплинг для баланса).

### Устранение позиционного смещения (Position Bias)

Модели часто переобучаются на ответы, находящиеся в начале документа. Данный блок параметров решает эту проблему:

* `position_balanced_sampling` (`true` / `false`) — включает механизм равновероятного попадания ответа в разные части (бины) окна контекста при обучении.
* `num_position_bins` (например, 4) — количество зон, на которые бьется окно (например, 0-25%, 25-50%, 50-75%, 75-100%).
* `position_bin_loss_weights` — веса функции потерь (CrossEntropy) для каждого бина. Позволяет сильнее "штрафовать" модель, если она ошибается на ответах в конце текста (например: `[1.0, 1.0, 1.4, 1.5]`).

## 🧠 Описание работы кода

Обучение разделено на два независимых скрипта, которые реализуют следующий пайплайн:

1. **Предобработка данных (Data Pipeline):**
* Скрипты читают очищенные `.jsonl` файлы (с удаленными HTML-тегами и yes/no вопросами).
* Датасет нарезается на окна с учетом `doc_stride` и `max_seq_length`. При активном `position_balanced_sampling` окна формируются динамически для равномерного распределения позиции ответа.


2. **Обучение (Training):**
* В качестве базовой архитектуры используется `AutoModelForQuestionAnswering`.
* Применяется оптимизированный класс `NQSpanTrainer`, который переопределяет метод `compute_loss` для учета пользовательских весов `position_bin_loss_weights`.
* Во время обучения логируются метрики и шаг за шагом сохраняются состояния.


3. **Оценка (Evaluation) и Постобработка:**
* После обучения (или на каждом шаге `eval_steps`) генерируются предсказания.
* Скрипт преобразует логиты модели обратно в текстовые спаны.
* Вычисляются классические для QA метрики: **Exact Match (EM)** и **F1-score** с официальной нормализацией SQuAD.
* Результаты сохраняются в формате JSON для дальнейшего визуального и статистического анализа.
