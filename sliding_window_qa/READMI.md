# Двухэтапный пайплайн QA: Reranker + Span Extractor (ModernBERT)

Данный проект реализует двухступенчатую архитектуру для извлечения ответов на вопросы (Extractive QA) на датасете Natural Questions (dev). Пайплайн использует sliding-window чанкинг с учетом границ предложений, кросс-энкодер для ранжирования чанков (Stage 1) и модель выделения спанов для финального ответа (Stage 2).

## 🚀 Ключевые особенности

* **Двухэтапный поиск (Two-Stage Pipeline):** Сначала оценивается релевантность пар (вопрос, чанк), затем из топ-K чанков извлекается точный ответ.


* **Умный чанкинг:** Окно контекста сдвигается с учетом границ предложений (точки, восклицательные и вопросительные знаки), чтобы не разрывать семантику текста.


* **Защита от OOM:** Встроенный механизм очистки памяти `torch.cuda.OutOfMemoryError`, который автоматически очищает кэш GPU и делит размер батча пополам для продолжения работы без падения скрипта.


* **Мониторинг ресурсов:** Подробное логирование потребления CPU/GPU памяти, пиковых значений и энергопотребления (через `nvidia-smi` и `psutil`).


* **Статистика и CI:** Расчет перцентильного Bootstrap CI (95% уровень доверия, 1000 ресэмплов) для всех метрик.

## 🔬 Архитектура пайплайна

### Stage 1: Cross-Encoder Reranker

В качестве реранкера используется архитектура `AutoModelForSequenceClassification`. Модель принимает на вход пару `(question, chunk_text)` и предсказывает скор релевантности.
Чанк считается положительным (label=1), если он целиком содержит хотя бы один золотой (gold) short-answer span.

### Stage 2: Span Extractor

Для извлечения ответа используется `AutoModelForQuestionAnswering`. Модель прогоняется только по топ-K чанкам, отранжированным на первом этапе. Скор каждого предсказанного спана вычисляется как сумма логитов начала и конца (`start_logit + end_logit`). В качестве финального предсказания выбирается спан с наивысшим скором среди всех топ-K чанков.

## 📊 Метрики

**Метрики ранжирования (Stage 1):**

* **MRR (Mean Reciprocal Rank)** — обратный ранг позиции первого чанка, содержащего правильный ответ (вклад 0, если таких чанков нет).


* **Recall@K** (для K=1, 3, 5) — доля вопросов, для которых в топ-K выдачи реранкера есть хотя бы один положительный чанк.



**Метрики извлечения спанов (Stage 2):**

* **Exact Match (EM)** — точное совпадение нормализованного предсказания и золотого ответа.


* **F1-score** — гармоническое среднее точности и полноты по токенам.


* **Token Recall** — доля токенов золотого ответа, найденных в предсказании.


* *Примечание:* Для метрик применяется SQuAD-подобная нормализация текста (удаление артиклей, пунктуации и лишних пробелов, приведение к нижнему регистру).

## 💻 Запуск эксперимента

Пример запуска пайплайна (PowerShell) со всеми необходимыми аргументами:

```powershell
python -m new_sliding_window.run_experiment ^
    --input-path "D:/data/nq/v1.0-simplified-nq-dev-all.jsonl.gz" ^
    --reranker-model-name "Alibaba-NLP/gte-reranker-modernbert-base" ^
    --span-model-name "C:/models/modernbert-qa-nq" ^
    --window-sizes 512 2048 ^
    --overlap-ratios 0.10 ^
    --batch-size 16 --span-batch-size 8 --span-top-k 3

```

### Основные флаги конфигурации

* `--input-path` — путь к NQ dev датасету (`*.jsonl.gz`) или директории с файлами. *Важно: скрипт фильтрует примеры, оставляя только те, где есть и валидный `long_answer`, и хотя бы один валидный `short_answer*`.


* `--reranker-model-name` — HF id или путь к весам кросс-энкодера.


* `--span-model-name` — HF id или путь к весам QA-модели.


* `--window-sizes` — список размеров окон (в токенах) для нарезки документа.


* `--overlap-ratios` — доля перекрытия между соседними окнами (например, `0.10`).


* `--batch-size` — размер батча для реранкера.


* `--span-batch-size` — размер батча для модели выделения спанов.


* `--span-top-k` — количество лучших чанков из Stage 1, которые передаются в Stage 2.


* `--span-max-seq-length` — максимальная длина последовательности для QA-модели.


* `--max-span-words` — ограничение на максимальную длину извлекаемого ответа в словах.

## 📁 Структура выходных данных

Результаты экспериментов сохраняются в директорию `logs_output_reranker/<run_name>/`. Для каждой комбинации `window_size` и `overlap_ratio` создается отдельная подпапка:

```text
logs_output_reranker/<run_name>/
├── run.log
└── win_<size>_ovr_<ratio>/
    ├── predictions.jsonl    # Построчные результаты: тексты чанков, скоры, извлеченный спан и gold-ответы
    ├── metrics.json         # Агрегированные метрики (MRR, Recall@K, EM, F1) с Bootstrap CI и профилированием времени
    └── memory_usage.json    # Лог использования CPU/GPU памяти и энергопотребления видеокарты

```
